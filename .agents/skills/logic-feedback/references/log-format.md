# FB記録の形式

1回のFBを1つのMarkdownファイルに残す。先頭のYAMLフロントマターに点数と指摘タグを入れ、後から grep で集計できるようにする。

## 保存先

`feedback-log/` に保存する。場所はリポジトリのルート（このリポジトリの外で使う場合は、作業中のプロジェクトのルート）。ユーザーが別の保存先を指定していればそれに従う。

ファイル名: `YYYY-MM-DD-HHMM-<題材を表す英小文字とハイフンの短い名前>.md`

例: `feedback-log/2026-10-01-1430-weekly-report.md`

日時は実行環境の現在時刻を使う（`date "+%Y-%m-%d-%H%M"` など）。

## テンプレート

```markdown
---
date: 2026-10-01T14:30
title: 週次報告の下書き
type: [A]
scores:
  構造: 2
  MECE: null
  推論: 3
  検証: 2
  分解: null
total: 47
tags: [結論が後ろ, 事実と解釈の混同]
revision_of: null
---

## 入力

（レビューした文章をそのまま貼る）

## FB

（ユーザーに返したFBをそのまま貼る）

## 本人のメモ

（任意。本人が気づいたことや、次に意識することを書く欄。空のままでよい）
```

### フィールド

- `type`: SKILL.md の入力の種類（A〜D）。複数ならすべて
- `scores`: 採点しなかった軸は `null`
- `total`: 100点満点の総合点
- `tags`: 指摘の種類。下の一覧から選ぶ。一覧にないものが必要なら追加してよいが、表記を揃える
- `revision_of`: 再提出のとき、前回の記録のファイル名。初回は `null`

### 指摘タグの一覧

| タグ | 意味 |
|---|---|
| 結論が後ろ | 結論が最後まで出てこない |
| 結論が不明 | 結論が読み取れない、または複数ある |
| 根拠不足 | 結論を支える根拠がない・足りない |
| 論理の飛躍 | 根拠から結論までに飛躍がある |
| 暗黙の前提 | 書かれていない前提に依存している |
| 観点が不明 | 分類の観点が書かれていない |
| 観点の混在 | 一つの分類に複数の観点が混ざっている |
| 具体レベル不揃い | 並んだ要素の抽象度がばらばら |
| 抜け | MECEの抜け |
| ダブり | MECEのダブり |
| 事実と解釈の混同 | 事実と意見・解釈が区別されていない |
| 根拠の未検証 | 根拠が正しいか確かめていない |
| バイアス | 認知バイアスの疑いがある |
| 抽象のみ | 具体例がなく抽象論だけ |
| 具体のみ | 具体の羅列で、まとめると何かがない |
| ゴール不明 | 何を決めるための検討かがわからない |
| 問いが未分解 | 検討が問いに分解されていない |

## 過去の記録の使い方

FBを書く前に、`feedback-log/` の直近の記録（10件程度）のフロントマターを確認する。

- 同じタグが3回以上出ていれば、FBの最後に「繰り返し出ている指摘」として伝える
- 同じ題材の前回の記録があれば、再提出として扱い、`revision_of` を埋めて点数を並べる
