# 採点基準

点数は「前回より良くなったか」を見るための物差し。毎回同じ基準でつけることが何より大事なので、印象ではなく下のアンカーに照らしてつける。

## 採点軸

入力の種類（SKILL.md のA〜D）に関係する軸だけを採点し、関係しない軸は「対象外」とする。

| 軸 | 何を見るか | 対象 |
|---|---|---|
| 構造 | 結論が先にあり、一文で言えるか。根拠とのつながりが見えるか | A, C（Bも結論があれば） |
| MECE | definitions.md のMECE成立条件1〜4 | B（A, C, Dで分類・列挙が出てくれば） |
| 推論 | 根拠から結論へ、第三者が検証可能なルールでたどれるか。推論の型ごとの弱点を押さえているか | C（A, Bで主張があれば） |
| 検証 | 根拠・過程・結論を確かめているか。バイアスへの自覚、事実と解釈の区別 | C（A, Bで主張があれば） |
| 分解 | 「検討」をゴール→問い→必要な情報→成果物に具体化できているか | D |

## 各軸のアンカー（1〜5）

迷ったら低い方をつける。

### 構造
- **1**: 結論が読み取れない
- **2**: 結論らしきものはあるが、最後まで読まないとわからない、または複数あって絞れない
- **3**: 結論は先にあるが、根拠とのつながりが読み手の補完に頼っている
- **4**: 結論→根拠の順で、つながりが追える。細部に余計な情報や順序の乱れがある
- **5**: 一読で結論と根拠の対応がわかる。指摘することがない

### MECE
- **1**: 観点が読み取れず、要素が並んでいるだけ
- **2**: 観点はあるが複数の軸が混ざっている、または具体レベルが大きくばらついている
- **3**: 観点は一つで具体レベルもほぼ揃っているが、抜けかダブりを具体的に示せる
- **4**: 条件1〜4を満たす。ただし観点が明示されておらず、読み手の推定に頼っている
- **5**: 観点が明示され、条件1〜4を満たし、抜け漏れダブりがないことを客観的に示せる

### 推論
- **1**: 根拠がない、または根拠と結論が無関係
- **2**: 根拠はあるが、結論までに大きな飛躍がある
- **3**: たどれるが、暗黙の前提が一つ以上あり、それが崩れると結論も崩れる
- **4**: 第三者がたどれる。推論の型の弱点（反例、事例の偏り、別の仮説）の一部が未検討
- **5**: 第三者がたどれ、推論の型の弱点も押さえている

### 検証
- **1**: 思い込みや伝聞をそのまま根拠にしている
- **2**: 事実と解釈・意見が区別されていない
- **3**: 事実と解釈は区別されているが、根拠が正しいかの確認が書かれていない
- **4**: 主な根拠は確かめてある。バイアスの可能性への言及がない
- **5**: 根拠・過程・結論のそれぞれを確かめ、バイアスの可能性も自分で潰している

### 分解
- **1**: 何を決めるための検討かがわからない
- **2**: ゴールはあるが、問いに分解されていない
- **3**: 問いに分解されているが、観点が混ざっている、または必要な情報が特定されていない
- **4**: ゴール・問い・必要な情報までは揃っている。成果物の形か期限が決まっていない
- **5**: ゴール→問い→必要な情報→成果物と期限まで具体化され、すぐ動ける

## 総合点

採点した軸の平均 × 20 を、小数点以下を四捨五入して100点満点で示す。

例: 構造4、推論3、検証2（MECE・分解は対象外）→ 平均3.0 → **60点**

## 書き方

- 各軸に、なぜその点数かを一行で添える。アンカーのどこに当たるかと、該当箇所の引用で示す
- 指摘の数と点数を整合させる。4点以下の軸には、その軸についての指摘を一つ以上つける
- 再提出の場合は前回の点数と並べる（例: 構造 2 → 4）
