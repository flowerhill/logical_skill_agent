# logical_skill_agent

論理的思考のフィードバックを受けるための、Claude Code 用スキルとエージェント。

報告・相談の下書きや検討メモを渡すと、MECE／論理的思考／クリティカルシンキングの観点で、上長役として構造面のレビューを返す。文章を直してもらうためではなく、構造的に考えるクセを身につけるために使う。

## 構成

```
.claude/
├── agents/
│   └── logic-reviewer.md        # 上長役のレビューエージェント（読み取り専用）
└── skills/
    └── logic-feedback/
        ├── SKILL.md             # FBの手順・チェック項目・出力形式
        └── definitions.md       # 判定基準となる定義集
```

## 使い方

このディレクトリを Claude Code で開いて使う。

スキルとして呼ぶ:

```
/logic-feedback
（レビューしてほしい文章を貼る）
```

エージェントに任せる:

```
logic-reviewer でこの報告文を見て
```

どのプロジェクトからでも使いたい場合は、`.claude/skills/logic-feedback` と `.claude/agents/logic-reviewer.md` を `~/.claude/` 配下にコピーする。

## 見てもらえるもの

| 種類 | 例 | 主に見る点 |
|---|---|---|
| 伝える文章 | 報告、相談、説明、チャット文 | 結論が先にあるか、根拠とつながっているか |
| 分解・整理 | 課題の洗い出し、選択肢の列挙 | MECE |
| 主張・判断 | 提案、結論、原因分析 | 推論の型と妥当性、検証 |
| 進め方の相談 | 「検討してください」と言われたが何をすればいいかわからない | 問いの分解 |

## FBの方針

- 判定基準は `definitions.md` の定義。一般論ではなく自分で決めた定義に照らす
- 指摘は優先度順に最大3つ。該当箇所を必ず引用する
- 書き直した完成版は最初から出さず、自分で直すための問いを返す。「直した例を見せて」と言えば例を出す
- 内容の正誤ではなく構造（結論・根拠・つながり・分け方）を見る

## カスタマイズ

- 定義を変える: `definitions.md`
- 厳しさや出し方を変える: `SKILL.md` の「FBの原則」
- エージェントの口調や役割を変える: `logic-reviewer.md`
